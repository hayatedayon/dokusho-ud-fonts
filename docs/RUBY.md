# ルビ仮名の試作（ss03）の現状と、続けるかどうかの判断材料

`ss03` を全仮名に広げるか、字ごとの手作業の調整まで進めるか、ここで止めるかは、利用者が決めます。この文書は決めるための事実を集めたものです。見積もりの数字や続行・中止の基準は書いていません。決まっていないことは「未決定」と書きます。測った数値は、`scripts/ruby_proof.py` が出力するもので、同じコマンドで再現できます。

## 今の ss03 の仕組みと限界

### 仕組み（`scripts/small_type.py`）

- 対象は `RUBY_KANA` の20字です。「あめぬれゃゅょっがぱ」と、対応する片仮名です。内訳は、清音の「あ・め・ぬ・れ」、濁音・半濁音の「が・ぱ」、小書きの「ゃ・ゅ・ょ・っ」が、平仮名と片仮名で10字ずつです。
- 字形は `trial_glyph` が作ります。原字の輪郭に、次の順で処理をします。
  1. 小書き仮名（8字）だけ 1.12 倍に拡大します。
  2. `embolden` で線を太らせます。横と縦に同じ量で、Regular は8ユニット（2048 em の0.39%）、Bold は4ユニット（0.20%）です。補強量はルビ仮名の20字すべてで同じです。
  3. インクの中心を原字のインクの中心に合わせて動かします。縦組の小書き仮名は、はみ出す場合だけ枠の内側へ戻します。
- 横組の字形のほか、縦組で `vert`・`vrt2` が選ぶ小書き仮名の縦組の字形（8字）にも、試作字形を作ります。1書体あたり、元の20字と合わせて28グリフです。
- 字送り・縦組の原点は原字と同じです。`palt`・`vpal` の詰め量は原字から引き継ぎます。
- 試作字形は原字（BIZ UD の仮名）と同じヒントの命令を持ちます（`hint_trial`。1.008 までは持ちませんでした）。付けられる理由は次のとおりです。
  1. 原字の命令は `SVTCA[0]`（y 方向）、`MDAP`・`SRP1`・`SRP2`・`IP`・`SHP`・`IUP` と、点の番号を積む `PUSHB`・`NPUSHB` だけです（4書体の28グリフすべて）。cvt を指す `MIAP`・`MIRP`、関数を呼ぶ `CALL`、`IF` は使いません。点の相対の命令と、グリッドへの丸め（`MDAP[1]`）だけなので、太らせた輪郭でも、拡大した輪郭でも働きます。1.004 で BIZ UDP の欧字に付けたときのような cvt の付け足しや、番号のずらしは要りません。
  2. 試作字形は原字の輪郭を拡大・補強・平行移動したもので、輪郭の数・終点・点の数と順序・on/off が、28グリフ × 4書体すべてで原字と同じです。点ごとに見ても、重心を引いた座標が原字の座標 × 拡大率から補強量の1.5倍以内にあります。そのため、点の番号がそのまま同じ点を指します。
  3. 命令は y 方向だけで、x 方向（`IUP[1]`）は動かしません。ヒントで動く点は横には動かず、縦に 1px 未満（FreeType で最大 61/64px）です。
  4. 縦組の小書き仮名の字形（`vert`・`vrt2` の置き換え先）も、それぞれの原字（BIZ UD の縦組の字形）の命令を持ちます。
  5. `maxp` の最大値は、原字がすでに持つ命令なので変わりません。変わるのは `glyf`・`loca` と、ファイル全体の `head.checkSumAdjustment` だけです。
- `ss03` を指定しない限り、字形は変わりません。`ruby` 機能（後述）とは別です。

### 限界（事実）

- 字ごとの調整はできません。拡大率（小書き仮名か否かの2通り）と補強量（書体の太さごとに1つ）が、仕組みに決まっているだけです。「ぬ・め」「れ・ね」のような、字によって潰れ方が違う字を個別に直す手段は、今の仕組みにはありません。
- 補強の方向は横と縦で同じです。`embolden` は縦横別の値を取れますが、今は同じ値を渡しています。
- 8ppem で、Regular の補強量は約0.03pxです（8 ÷ 2048 × 8ppem）。
- フォントの prep は8ppem 未満で命令を止めます。そのため、6・7ppem の通常の仮名はヒントを動かす環境でもヒントなしと同じ画素で描かれます（4書体、平仮名と片仮名の20字、FreeType v35・v40 とも）。試作字形も同じ命令を持つので、6・7ppem は変わりません。
- gasp は `{7: 10, 65535: 15}` で、7ppem 以下ではグリッドに合わせません。
- ほかの機能との組み合わせは次のとおりです（HarfBuzz、4書体。`check_ruby_combinations` が1〜3を検査します）。
  1. 分解した濁音（か＋U+3099）は、`ccmp` で合成してから `ss03` の字形になります。合成済みの「が」と同じ字形・送りです。横組・縦組とも同じです。
  2. 20字の後ろの結合濁点・半濁点（U+3099・U+309A）は、記号の字形・送り・位置が変わらず、仮名だけが試作字形になります。小書き仮名は1.12倍になるため、仮名のインクの中心と記号の位置の差が、最大で33ユニット（1.6% em）動きます。
  3. 「か゚」などの合字（か・き・く・け・こ・カ・キ・ク・ケ・コ・セ・ツ・ト・ㇷ ＋ U+309A）は20字に入らず、`ss03` で変わりません。前後の字は通常どおり試作字形になります。
  4. `aalt` を指定すると、`aalt` の置き換えが先に働き、半角の候補（あ → 半角の字形）になって、`ss03` は効きません。`hwid` も同じです。`fwid` と `ss03` を併用すると、試作字形になります。試作字形は `aalt` の候補に入っていません。この動作は `ss03` を足す前からの `aalt` の並びによるもので、フォントは直していません。直すかどうかは未決定です。
- 通常の `ruby` 機能が置き換えるのは、`、` と `。` の2字だけです（`uni3001` → `uniFE45`、`uni3002` → `uniFE46`）。元の BIZ UD の `ruby` 機能も同じです。仮名は置き換えません。

## 見本の見方

`.venv/bin/python scripts/ruby_proof.py` が `dist/ruby-trial.html` を作ります（FreeType の結果で、Windows・macOS の実機の描画とは別です。画像は上が実寸、下が同じ画素の4倍です）。配るフォントの字形は変えません。

- **ヒントの有無をそろえた比較（3-a）**: 同じ字を「通常・ヒントあり」「通常・ヒントなし」「試作・ヒントなし」「試作・ヒントあり」の4つで並べます。本文12〜20pxのルビは6〜10ppem です。「通常・ヒントなし」「試作・ヒントなし」は、見本のために FreeType でヒンティングを動かさずに描いた字です（フォントには入れません）。1と2の差が通常字のヒントの差、2と3の差が補強（と小書き仮名の拡大）の差、3と4の差が試作字形のヒントの差です。1と4の差は、補強と拡大だけの差に近くなります。64px の拡大も並べます。
- **gasp を守る描画（3-b）**: `freetype_render.Renderer` は、`respect_gasp=True` で、gasp がグリッドに合わせないとする大きさでヒントを使いません。既定は `False` で、検査はこれまでどおりです。見本は「守る環境」「守らない環境」の両方を、FreeType v40 と v35 で出します。
- **補強量を広く試す比較（3-c）**: 現在の補強量に倍率を掛けて、補強なし・今の値・2倍・4倍・横線だけ4倍・縦線だけ4倍を、ヒントなしで6〜10ppem と64pxの拡大で並べます。補強量を変えた字形は見本の中だけで、配るフォントを読み直して作ります。「横線だけ」は縦方向に太らせ（`embolden` の `ey`）、「縦線だけ」は横方向に太らせます（`ex`）。

### 見本から読み取れたこと

4書体・平仮名と片仮名の20字の合計で、FreeType v40 の値です（v35 も同じ値でした）。「画素数」は濃さが違う画素の数、「濃さの差」はインク1画素分を単位にした濃さの差の合計です。

| ppem | 通常のヒントの差（画素数 / 濃さの差） | 補強の差（ヒントなし同士） | 通常・ヒントあり と 試作・ヒントなし（1.008 までの描画） | 通常・ヒントあり と 試作・ヒントあり（今） |
| --- | --- | --- | --- | --- |
| 6 | 0 / 0 | 1691 / 80 | 1691 / 80 | 1691 / 80 |
| 7 | 0 / 0 | 2141 / 116 | 2141 / 116 | 2141 / 116 |
| 8 | 2600 / 291 | 2568 / 159 | 2884 / 380 | 2389 / 235 |
| 9 | 3084 / 338 | 3146 / 216 | 3372 / 440 | 2848 / 267 |
| 10 | 3626 / 458 | 3725 / 272 | 3996 / 600 | 3447 / 354 |

- 6・7ppem は、ヒントによる差がありません。見える差は補強と小書き仮名の拡大によるものだけです。試作字形にヒントを付けても、6・7ppem の画素は変わりません（試作・ヒントありと試作・ヒントなしの差は0画素）。
- 8〜10ppem では、ヒントを付ける前は、ヒントなしの試作とヒントありの通常字の濃さの差が、補強の差の約2.0〜2.4倍ありました（380 / 159、440 / 216、600 / 272）。ヒントを付けると、約1.2〜1.5倍（235 / 159、267 / 216、354 / 272）に下がり、ヒントなしの試作との濃さの差の約38〜41%が減ります。残りは補強と拡大の差に、拡大した小書き仮名の位置の違いなどが加わったものです。
- 試作字形のヒントそのものによる差（試作・ヒントなしと試作・ヒントありの差）は、通常字のヒントの差とほぼ同じ大きさです（8〜10ppem で濃さの差が308・352・484。通常字は291・338・458）。
- ヒントを付けても、インクの量は変わりません（試作・ヒントなしを1として、8ppem 1.001、9ppem 0.988、10ppem 1.000。4書体の合計）。通常・ヒントなしに対する比は約1.11で、補強と拡大だけの量のままです。
- 横線の端が画素の境目にそろう割合（同じ高さに3点以上ある横線のうち、64分の1画素の座標が64の倍数のもの。8〜10ppem、4書体・28グリフの合計）は、通常・ヒントありが約0.35〜0.37、試作・ヒントありが約0.36〜0.38、試作・ヒントなしが約0.02です。
- 試作字形のうち、ヒントで境界のにじみ（中間の濃さの画素）が減らない字が3つあります。「ッ」（横組・縦組）と「メ」です（FreeType v40、8〜10ppem、4書体の合計で「ッ」はヒントなし91.2 に対してヒントあり94.1、縦組の「ッ」は91.0 に対して94.3、「メ」は80.5 に対して80.8）。ほかの25グリフは減ります。この3つも、形は崩れず、インクの量はヒントなしの0.8〜1.4倍以内です（グレースケール、8〜24ppem の全字）。1ビットのモノクロ（FreeType v35 mono）では量子化のため、字ごとのインクの量がヒントなしの約0.6〜1.6倍動きますが、通常の仮名も同じように動きます（4書体の合計では、各 ppem で0.9〜1.1倍以内）。
- gasp を守る環境と守らない環境で、画素は同じでした。通常の仮名と試作字形のヒントが、prep で6・7ppem で止まっているためです。
- インクの量は通常・ヒントなしを1とすると、補強なしの試作が約1.08倍（小書き仮名の拡大だけ）、今の値が Mincho Regular で約1.14〜1.15倍、Mincho Bold と Gothic Bold で約1.10倍、Gothic Regular で約1.14倍です。4倍にすると Mincho Regular で約1.35倍です。横線だけ4倍と縦線だけ4倍は、2倍とほぼ同じ量（Mincho Regular で約1.21倍）になります。

これらの数値は見た目の読みやすさを表すものではありません。読みやすさは見本の画像を実寸で見て判断してください。

## 全仮名に広げるときの対象の字

数えた範囲は、平仮名（U+3041〜3096）、片仮名（U+30A1〜30FA と、U+30A0）、小書きの片仮名拡張（U+31F0〜31FF）です。4書体とも同じ数でした。

| 区分 | 字数 | 今の ss03 | 残り |
| --- | --- | --- | --- |
| 平仮名の清音など | 48 | 4（あ・め・ぬ・れ） | 44 |
| 平仮名の濁音・半濁音（ゔを含む） | 26 | 2（が・ぱ） | 24 |
| 平仮名の小書き（ゕゖを含む） | 12 | 4（ゃ・ゅ・ょ・っ） | 8 |
| 片仮名の清音など（゠と・を含む） | 50 | 4 | 46 |
| 片仮名の濁音・半濁音（ヷヸヹヺ・ヴを含む） | 30 | 2 | 28 |
| 片仮名の小書き（ヵヶを含む） | 12 | 4 | 8 |
| 小書きの片仮名拡張 | 16 | 0 | 16 |
| 合計 | 194 | 20 | 174 |

- グリフの数は横組の字形が194、縦組で別の字形になる字が41（小書き仮名の40字と ゠）で、1書体235グリフです。4書体で940グリフです。今の `ss03` は1書体28グリフ、4書体で112グリフです。
- 長音符 `ー`、繰り返し記号（ゝ・ゞ・ヽ・ヾ）、ゟ・ヿ は含めていません。この7字を足す場合は、横組7、縦組で別の字形になる字が5（ー・ゝ・ゞ・ヽ・ヾ）で、1書体12グリフ、4書体で48グリフ増えます。
- 結合濁点・半濁点（U+3099・U+309A）、全角の記号 ゛゜（U+309B・309C）は含めていません。

## ruby 機能に広げる場合に、公開済みの動作がどう変わるか

- 今の `ruby` 機能は `、。` の2字だけを置き換えます。仮名を `ruby` 機能に入れると、`ruby` 機能を有効にする文書や組版環境で、ルビの仮名の字形が試作字形（またはその後の字形）になります。見た目は変わりますが、字送りと縦組の原点は原字と同じなので、組み方（行の折り返しなど）は変わらない設計です。
- どの環境が `ruby` 機能を自動で有効にするか（CSS の `font-variant-east-asian: ruby` を指定するか、ルビの注記に自動で使うか）は、調べていません。
- `ss03` を残すか、`ruby` に統合して廃止するかで、1.007 から公開している `ss03` の動作が変わります。`ss03` を指定している文書があれば、字形が変わります。公開済みのファイルは差し替えられないので、変えた内容は新しい版の FONTLOG に書くことになります。
- `ss03` の20字の字形を調整し直した場合も、同じく `ss03` を指定している文書の見た目が変わります。

## 輪郭の個別調整を管理する方法の選択肢

事実だけを書きます。選ぶのは利用者です。いずれも元の BIZ UD の輪郭を使い、依存を増やさない（fontTools のみ）前提です。

| 方法 | できること | 長所 | 短所 |
| --- | --- | --- | --- |
| A. 変換のパラメータを字ごとに持つ（拡大率・縦横別の補強量・平行移動を、`scripts/` の辞書にする） | 今の仕組みの延長。字ごとに数値を変えられる | ビルドが今のまま再現できる。差分が数値でレビューしやすい。縦組の字形にも同じ処理を適用できる | 表現できるのは拡大・縦横の補強・平行移動だけ。交差部の潰れなど、輪郭の局所的な編集はできない |
| B. 輪郭の差分を持つ（原字の点に対する移動量などを、データファイルにする） | 点単位の移動で、輪郭を局所的に変えられる | 元の輪郭から離れすぎない。ビルドで再現できる | 元のフォントの点の数・並びに依存し、元のフォントの版を固定している間だけ有効（`scripts/sources.json`）。差分を作る道具が要る。データの読みにくさ |
| C. 手で描いた輪郭を、別のソースファイル（SVG など）として持つ | 任意の形にできる | 通常のフォント制作の流れ。輪郭を直接見て直せる | 編集の道具がこのリポジトリにない。ヒントの付け方を決める必要がある。元の BIZ UD との関係（派生の表示）を整理する必要がある。字形1つずつ（横組・縦組・4書体）の数が多い |

どの方法でも、4書体 × 235グリフ（全仮名の場合）の確認が要ります。
