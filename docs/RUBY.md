# ルビ仮名の試作（ss03）の仕組み・限界・測った数値

`ss03` は仮名の全194字に、同じ処理（方法 A の範囲。後述）を当てた試作です。この文書は、その仕組み、限界、測った数値、まだ決まっていないことをまとめたものです。測った数値は、`scripts/ruby_proof.py` が出力するもので、同じコマンドで再現できます。決まっていないことは「未決定」と書きます。

## ss03 の仕組みと限界

### 仕組み（`scripts/small_type.py`）

- 対象は `RUBY_KANA` の194字です。平仮名（U+3041〜3096）、片仮名（U+30A0〜30FB。゠と・を含む）、小書きの片仮名拡張（U+31F0〜31FF）です。長音符 `ー`、繰り返し記号（ゝ・ゞ・ヽ・ヾ）、ゟ・ヿ、結合濁点・半濁点（U+3099・U+309A）、全角の記号 ゛゜（U+309B・309C）は含みません。内訳は後述の表にあります。1.009 までは、「あめぬれゃゅょっがぱ」と対応する片仮名の20字でした。
- 字形は `trial_glyph` が作ります。原字の輪郭に、次の順で処理をします。字ごとの調整はしません。
  1. 小書き仮名（40字。平仮名の「ぁぃぅぇぉっゃゅょゎゕゖ」、片仮名の「ァィゥェォッャュョヮヵヶ」、小書きの片仮名拡張の16字）だけ 1.12 倍に拡大します。「・」を含むほかの字は拡大しません。
  2. `embolden` で線を太らせます。横と縦に同じ量で、Regular は8ユニット（2048 em の0.39%）、Bold は4ユニット（0.20%）です。補強量は194字すべてで同じです。
  3. インクの中心を原字のインクの中心に合わせて動かします。縦組の小書き仮名は、はみ出す場合だけ枠の内側へ戻します。
- 横組の字形のほか、縦組で `vert`・`vrt2` が選ぶ別の字形（41字。小書き仮名の40字と ゠）にも、試作字形を作ります。1書体あたり194＋41＝235グリフ、4書体で940グリフです（1.009 までは1書体28グリフでした）。
- 字送り・縦組の原点は原字と同じです。`palt`・`vpal` の詰め量と、結合用の記号を付ける位置（`mark`）は原字から引き継ぎます。
- 試作字形は原字（BIZ UD の仮名）と同じヒントの命令を持ちます（`hint_trial`。1.008 までは持ちませんでした）。付けられる理由と、付けない字は次のとおりです。条件は `trial_hint_issues` が判定し、`check_ruby_hint_programs` が4書体の全グリフで確かめます。
  1. 原字の命令は `SVTCA[0]`（y 方向）、`MDAP`・`SRP1`・`SRP2`・`IP`・`SHP`・`IUP` と、点の番号を積む `PUSHB`・`NPUSHB` などだけで、`SVTCA[1]` はありません。cvt を指す `MIAP`・`MIRP`、関数を呼ぶ `CALL`、`IF` は使いません。点の相対の命令と、グリッドへの丸め（`MDAP[1]`）だけなので、太らせた輪郭でも、拡大した輪郭でも働きます。1.004 で BIZ UDP の欧字に付けたときのような cvt の付け足しや、番号のずらしは要りません。
  2. 試作字形は原字の輪郭を拡大・補強・平行移動したもので、輪郭の数・終点・点の数と順序・on/off が、235グリフ × 4書体すべてで原字と同じです。そのうえで点ごとに、重心を引いた座標が原字の座標 × 拡大率から補強量の1.5倍＋2ユニット以内にあることを条件にします。この条件を満たすと、点の番号がそのまま同じ点を指します。
  3. 命令の下で動くのは y 方向だけで、x 方向は動きません。原字の命令には `IUP[1]` も含まれますが、`SVTCA[0]` の下で x 方向に触れた点がないので、何も動かしません。ヒントで動く点は横には動かず、縦に 1px 以内（検査は64/64px以内）です。FreeType の全描画モードで、x 座標が変わらないことを検査します。
  4. 縦組の別の字形（`vert`・`vrt2` の置き換え先）も、それぞれの原字（BIZ UD の縦組の字形）の命令を持ちます。
  5. 条件 2 の点の対応を満たさない字は、ヒントを付けません。4書体の940グリフのうち16グリフで、それぞれ1〜2点だけが条件を0.1〜7.9ユニット超えます（鋭い角の点が補強で外へずれるため）。明朝 Regular は「そ・ぞ・む」、明朝 Bold は「こ・ご・ゆ・ォ（縦組）」、ゴシック Regular は「す・ず・そ・ぞ・ゑ」、ゴシック Bold は「そ・て・で・ゑ」です。残りの924グリフ（明朝 Regular 232、明朝 Bold 231、ゴシック Regular 230、ゴシック Bold 231）はヒントを持ちます。命令を持たない16グリフは、`NO_HINTING` で描いたのと同じ画素になります。
  6. `maxp` は `numGlyphs` だけが変わります（14368 → 14575。足したグリフは207）。命令の最大値（`maxSizeOfInstructions`・`maxStackElements` など）は、原字がすでに持つ命令なので変わりません。
- `ss03` を指定しない限り、字形は変わりません（1.010 の候補のビルドとの比較と、全文字の HarfBuzz の組みの比較で確かめました。後述）。`ruby` 機能（後述）とは別です。

### 限界（事実）

- 字ごとの調整はできません。拡大率（小書き仮名か否かの2通り）と補強量（書体の太さごとに1つ）が、仕組みに決まっているだけです。「ぬ・め」「れ・ね」のような、字によって潰れ方が違う字を個別に直す手段は、今の仕組みにはありません。
- 補強の方向は横と縦で同じです。`embolden` は縦横別の値を取れますが、今は同じ値を渡しています。
- 8ppem で、Regular の補強量は約0.03pxです（8 ÷ 2048 × 8ppem）。
- フォントの prep は8ppem 未満で命令を止めます。そのため、6・7ppem の通常の仮名はヒントを動かす環境でもヒントなしと同じ画素で描かれます（4書体、194字、FreeType v35・v40 とも）。試作字形も同じ命令を持つので、6・7ppem は変わりません。
- gasp は `{7: 10, 65535: 15}` で、7ppem 以下ではグリッドに合わせません。
- 「・」（U+30FB）は、1〜2px ほどの点なので、原字のヒントがインクの量を大きく動かします（8〜24ppem で、ヒントなしに対する量が約0.56〜1.58倍。原字の「・」も同じ動きです）。試作字形の「・」はこの動きを原字から引き継ぎます。検査（`check_ruby_hint_rendering`）は、原字と同じ動き（差が0.1以内）なら許します。
- ほかの機能との組み合わせは次のとおりです（HarfBuzz、4書体。`check_ruby_combinations` が1〜4を検査します）。
  1. 分解した濁音（か＋U+3099）は、`ccmp` で合成してから `ss03` の字形になります。合成済みの「が」と同じ字形・送りです。横組・縦組とも同じです。対象は、NFD で分解できる仮名の全部です。
  2. 194字の後ろの結合濁点・半濁点（U+3099・U+309A）は、記号の字形・送り・位置が変わらず、仮名だけが試作字形になります。記号の位置は原字の仮名の錨のままなので、小書き仮名は輪郭が1.12倍になる分、仮名の輪郭の端が最大129ユニット（6.3% em。ゴシック Bold の「ゅ」）動き、記号との間隔が変わります。インクの中心の差は最大36ユニット（1.8% em。明朝 Bold の「ゖ」）です。
  3. 「か゚」などの合字（か・き・く・け・こ・カ・キ・ク・ケ・コ・セ・ツ・ト・ㇷ ＋ U+309A）は対象外で、`ss03` で変わりません。前後の字は通常どおり試作字形になります。
  4. `aalt` を指定すると、`aalt` の置き換えが先に働き、半角の候補（あ → 半角の字形）になって、`ss03` は効きません。`hwid` も同じです。`fwid` と `ss03` を併用すると、試作字形になります。試作字形は `aalt` の候補に入っていません。この動作は `ss03` を足す前からの `aalt` の並びによるもので、フォントは直していません。直すかどうかは未決定です。
- 通常の `ruby` 機能が置き換えるのは、`、` と `。` の2字だけです（`uni3001` → `uniFE45`、`uni3002` → `uniFE46`）。元の BIZ UD の `ruby` 機能も同じです。仮名は置き換えません。

## 見本の見方

`.venv/bin/python scripts/ruby_proof.py` が `dist/ruby-trial.html` を作ります（FreeType の結果で、Windows・macOS の実機の描画とは別です。画像は上が実寸、下が同じ画素の4倍です）。配るフォントの字形は変えません。194字は、平仮名・片仮名・小書きの片仮名拡張の順に、1行24字までに分けて並べます。

- **全グリフの一覧（0）**: 4書体ごとに、通常字・試作字形（ヒントなし）・試作字形（ヒントあり）を40pxで並べます。横組の194字のあとに、縦組で別の字形になる41字が続きます（縦組の字形は字を縦に並べず、1字ずつ横に並べます）。崩れた字を探すための一覧です。
- **ヒントの有無をそろえた比較（1）**: 同じ字を「通常・ヒントあり」「通常・ヒントなし」「試作・ヒントなし」「試作・ヒントあり」の4つで並べます。本文12〜20pxのルビは6〜10ppem です。「通常・ヒントなし」「試作・ヒントなし」は、見本のために FreeType でヒンティングを動かさずに描いた字です（フォントには入れません）。1と2の差が通常字のヒントの差、2と3の差が補強（と小書き仮名の拡大）の差、3と4の差が試作字形のヒントの差です。1と4の差は、補強と拡大だけの差に近くなります。64px の拡大も並べます。画像は FreeType v40・gasp を守らない環境だけに並べ、ほかは数値だけです（画素は同じでした）。
- **gasp を守る描画（2）**: `freetype_render.Renderer` は、`respect_gasp=True` で、gasp がグリッドに合わせないとする大きさでヒントを使いません。既定は `False` で、検査はこれまでどおりです。見本は「守る環境」「守らない環境」の両方を、FreeType v40 と v35 で出します。
- **補強量を広く試す比較（3）**: 現在の補強量に倍率を掛けて、補強なし・今の値・2倍・4倍・横線だけ4倍・縦線だけ4倍を、ヒントなしで6〜10ppem と64pxの拡大で並べます。補強量を変えた字形は見本の中だけで、配るフォントを読み直して作ります。「横線だけ」は縦方向に太らせ（`embolden` の `ey`）、「縦線だけ」は横方向に太らせます（`ex`）。
- **ヒントでにじみが増える字**: 試作字形ごとに、ヒントあり・なしの境界のにじみを測った表です（後述）。

- 8〜10ppem では、ヒントを付ける前は、ヒントなしの試作とヒントありの通常字の濃さの差が、補強の差の約3.3〜3.8倍ありました（3556 / 939、4327 / 1237、5264 / 1579）。ヒントを付けると、約1.4〜1.7倍（1579 / 939、1813 / 1237、2171 / 1579）に下がり、ヒントなしの試作との濃さの差の約56〜59%が減ります（20字のときは約38〜41%でした）。
- 試作字形のヒントそのものによる差（試作・ヒントなしと試作・ヒントありの差）は、通常字のヒントの差とほぼ同じ大きさです（8〜10ppem で濃さの差が3161・3789・4557。通常字は3054・3804・4545）。

- gasp を守る環境と守らない環境で、画素は同じでした。通常の仮名と試作字形のヒントが、prep で6・7ppem で止まっているためです。
- インクの量は通常・ヒントなしを1とすると、補強なしの試作が約1.05倍（小書き仮名の拡大だけ）、今の値が Mincho Regular で約1.12倍、Gothic Regular で約1.11倍、Mincho Bold と Gothic Bold で約1.07倍です。4倍にすると Mincho Regular で約1.33倍です。横線だけ4倍と縦線だけ4倍は、2倍とほぼ同じ量（Mincho Regular で約1.19倍）になります。

## 1.010 の候補のビルドとの違い

`work/safari-candidate`（`007c335`）のビルドと、`ss03` を194字に広げたビルドを、同じ元のフォントから作って比べました（4書体）。

- テーブルの集合は同じで、変わったのは `glyf`・`loca`・`hmtx`・`vmtx`・`hhea`・`vhea`・`GSUB`・`GPOS`・`GDEF`・`maxp`（`numGlyphs` だけ）・`OS/2`（`xAvgCharWidth` が1増える）・`head`（`checkSumAdjustment`）です。`cmap`・`post` は同じです。
- `ss03` の置き換え先以外のグリフ（14340グリフ）は、並びも、輪郭・命令・`hmtx`・`vmtx` も同じです。`ss03` の置き換え先は28から235になり、増えた207グリフはすべて `ss03` の置き換え先です。1.009 までの28グリフは、座標・命令・`hmtx`・`vmtx` とも同じです。
- GSUB は `ss03`・`vert`・`vrt2` の3つの機能の置き換え（lookup 3つ）だけが変わります。GPOS は `palt`・`vpal`（置き換え先の値は原字と同じ）と、結合用の記号を付ける `mark` の（基底字に置き換え先を足した）lookup だけが変わります。`GDEF` の変更は、置き換え先のグリフの分類だけです。
- 作った4書体のすべての文字（cmap の全字、濁点・半濁点の組み合わせなど）を、`ss03` なしで HarfBuzz で組み（`aalt`・`palt`・`vpal`・`halt`・`vhal`・`hwid`・`fwid`・`ruby`・`ss01`・`ss02`・`vert`・`vrt2` の指定も、横組・縦組で）、字形（輪郭・命令・`hmtx`・`vmtx`）・送り・ずれを比べました。違いは0でした（のべ約28万回）。
- ファイルの大きさ（TTF）は、明朝 Regular が6264152 → 6323652バイト、明朝 Bold が7220352 → 7300556、ゴシック Regular が4761220 → 4795796、ゴシック Bold が4731840 → 4766124です（WOFF2は、明朝 Regular が2914468 → 2933400、明朝 Bold が3709924 → 3732548、ゴシック Regular が2212964 → 2227756、ゴシック Bold が2255788 → 2267700）。

## ruby 機能に統合する場合に、公開済みの動作がどう変わるか（今は統合していません）

- `ruby` 機能は `、。` の2字だけを置き換えます。仮名を `ruby` 機能に入れると、`ruby` 機能を有効にする文書や組版環境で、ルビの仮名の字形が試作字形（またはその後の字形）になります。見た目は変わりますが、字送りと縦組の原点は原字と同じなので、組み方（行の折り返しなど）は変わらない設計です。
- どの環境が `ruby` 機能を自動で有効にするか（CSS の `font-variant-east-asian: ruby` を指定するか、ルビの注記に自動で使うか）は、調べていません。
- `ss03` を `ruby` に統合して廃止すると、1.007 から公開している `ss03` の動作が変わります。`ss03` を指定している文書があれば、字形が変わります。公開済みのファイルは差し替えられないので、変えた内容は新しい版の FONTLOG に書くことになります。
- 1.009 までの20字の字形を調整し直した場合も、同じく `ss03` を指定している文書の見た目が変わります。

## 輪郭の個別調整を管理する方法の選択肢

事実だけを書きます。選ぶのは利用者です。いずれも元の BIZ UD の輪郭を使い、依存を増やさない（fontTools のみ）前提です。

| 方法 | できること | 長所 | 短所 |
| --- | --- | --- | --- |
| A. 変換のパラメータを字ごとに持つ（拡大率・縦横別の補強量・平行移動を、`scripts/` の辞書にする） | 今の仕組みの延長。字ごとに数値を変えられる | ビルドが今のまま再現できる。差分が数値でレビューしやすい。縦組の字形にも同じ処理を適用できる | 表現できるのは拡大・縦横の補強・平行移動だけ。交差部の潰れなど、輪郭の局所的な編集はできない |
| B. 輪郭の差分を持つ（原字の点に対する移動量などを、データファイルにする） | 点単位の移動で、輪郭を局所的に変えられる | 元の輪郭から離れすぎない。ビルドで再現できる | 元のフォントの点の数・並びに依存し、元のフォントの版を固定している間だけ有効（`scripts/sources.json`）。差分を作る道具が要る。データの読みにくさ |
| C. 手で描いた輪郭を、別のソースファイル（SVG など）として持つ | 任意の形にできる | 通常のフォント制作の流れ。輪郭を直接見て直せる | 編集の道具がこのリポジトリにない。ヒントの付け方を決める必要がある。元の BIZ UD との関係（派生の表示）を整理する必要がある。字形1つずつ（横組・縦組・4書体）の数が多い |

どの方法でも、4書体 × 235グリフの確認が要ります。

## 未決定の事項

- 実環境（Windows・macOS・Hayate Reader の WebView）で、gasp を守る描き方になるかの確認と、`ss03` が194字すべてに効くことの確認
