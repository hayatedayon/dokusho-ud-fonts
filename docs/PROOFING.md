# 読書 UD の校正

## 見本を作る

リポジトリのルートで実行します。環境が未準備なら、先に [作り方](DEVELOPMENT.md#作り方) に従って仮想環境と依存パッケージを用意してください。

```sh
.venv/bin/python scripts/build.py
.venv/bin/python scripts/check.py
.venv/bin/python scripts/specimen_page.py
.venv/bin/python scripts/overflow_page.py
.venv/bin/python scripts/proof_page.py
python3 -m http.server 8000
```

CI の `DokushoUD-proof` 成果物を使う場合は、展開したルートで HTTP サーバーを起動するだけです。フォントのビルド・検査・アップロードは必須で、先に完了させます。見本の生成とアップロードは補助ステップとし、その失敗ではリリースを止めません。生成は３分、アップロードは２分の制限を設けています（ジョブ全体の上限は15分）。生成に失敗した場合は見本のアップロードを省略するため、成果物がないことがあります。CI の該当ステップで結果を確認してください。

| ページ | 確認するもの |
| --- | --- |
| `http://localhost:8000/dist/specimen.html` | カーニング、引用符、記号、ルビ仮名、数字、詰め機能の切り替え。BIZ UD・BIZ UDP との比較 |
| `http://localhost:8000/dist/proof.html` | １行32字分・奥行き50em・行送り1.75の固定版面。画面用12・14・16px、印刷用9〜12pt、縦横組 |
| `http://localhost:8000/dist/small-type.html` | 数字のヒント有無とルビ仮名の試作を、FreeType の１倍と４倍画像で比較（１画像pxを１画面pxに対応させるにはDPR 1・ズーム100%）。フォントの SHA-256 も表示 |
| `http://localhost:8000/dist/overflow.html` | 元フォントから受け継いだ、行の上下からはみ出す文字 |

固定版面は、元と比較するときに書体・大きさ・縦横組をそろえます。欧字カーニングは改行位置も変えます。１字ずつの見え方に加え、本文全体の濃さ、行のアキ、読書中に目が止まる所を確認してください。

## 組版機能

| 用途 | 指定 | 併用の注意 |
| --- | --- | --- |
| 本文 | 和文は既定のベタ組、`kern` は既定で有効 | `font-kerning: none` で欧字カーニングを切れる |
| 横組の見出し | `palt` | `chws`・`halt` を切り、CSS では `text-spacing-trim: space-all` |
| 縦組の見出し | `vpal` | `vchw`・`vhal` を切り、CSS では `text-spacing-trim: space-all` |
| 表・目次の数字 | `tnum` | `pnum` で元のプロポーショナル数字へ戻せる。両方指定すると `pnum` が優先 |
| 和文の引用符 | `ss01`「和文引用符」 | `‘ ’ “ ”` を BIZ UD の全角の字へ戻す。`fwid` 併用時も全角になる。縦組も対応 |
| 欧文用の記号 | `ss02`「欧文記号」 | 日本語文書でも対象の記号を BIZ UDP にする。引用符は対象外なので `ss01` と併用できる。`hwid`・`fwid` 併用時はその幅機能だけを指定した従来の結果を保つ |
| ルビ仮名の試作 | `ss03`「ルビ仮名（試作）」 | 対象は「あめぬれゃゅょっがぱ」と対応する片仮名の20字。ルビだけに指定する。`palt`・`vpal` の詰め量は元の仮名から引き継ぐ |

`ss03` は字形を選ぶ機能です。ルビの大きさと位置はアプリ側で指定します。枠は全角のままなので、ルビをもう一度小さくする機能ではありません。小書き仮名を12%拡大し、線を少し補強した限定的な試作です。完全なルビ専用書体や可読性の向上を保証するものではなく、既存の `ruby` 機能も変更していません。試作字形にはヒンティングがなく、通常字には元のヒントが残るため、ラスタ比較には字形とヒント有無の両方の差が含まれます。

カーニングの初期値は `scripts/kerning.py` の em 千分率で管理しています。文字の輪郭は変えません。和文の字、全角欧字、`hwid` の半角、`tnum` の数字、縦組用の置換先の字は対象外です。縦組中の横倒し欧字を横組として組む場合はカーニングの対象になります。`check.py` の縦組検査は `vert`・`vrt2` の置換先についての検査です。

## 自動検証

`check.py` は元との輪郭・字幅・ヒンティング・組み方の一致を引き続き検査します。組み方の比較では新しい `kern` を切り、カーニングの検査は別に行います。

- `kerning.PAIRS` で宣言した全ペアをアクセント付き・除外字まで展開し、HarfBuzzで組んだときの送りの差が設定値と一致すること。できたGPOSの実効量もHarfBuzzと突き合わせ、接触検査とは独立に、効かなくなったペアを検出する。
- GPOSの展開は、ゼロ値も含めて最初に一致したサブテーブルを優先すること。Format 1/2の混在、クラス0の暗黙のゼロ、明示的なゼロ、別lookupの処理を小さな表で検査する。実効ペアのインクの隙間が1% em以上あり（水平断面と、斜めを含む輪郭間の最短距離の両方）、等幅の字と縦組を変えないこと。
- `kern` の全入力字が、`hwid`・`fwid`・`tnum`・`vert`・`vrt2` の全置換先と重ならないこと。
- `pnum` が `tnum` を元に戻し、`zero`・`frac` との併用を壊さないこと。
- `ss01`・`ss02` の結果が元の BIZ UD・BIZ UDP と一致し、２つを併用できること。日本語・英語、横組・通常の縦組・`vert=0,vrt2` の縦組で確認する。
- `ss02` と `hwid`・`fwid` の併用で、幅指定だけの場合の字形・送り・配置を保つこと。記号単独・和文中・欧文中、言語指定ja/en、縦横組で全対象字を組んで確かめる。
- `ss02` の横組・縦組の全候補が通常の `locl` 出力・cmap と別の複製であり、輪郭・メトリクス・ヒント・GDEFクラスを保つこと。幅補正の入力として除外できるのも、この複製だけに限る。`ss02` 無効時の `hwid`・`fwid` は、公開1.006の956字×８条件の固定値・字形と配置のハッシュに一致すること。生成側のデータや、現在のフォント同士の比較を基準にしない。
- 試作ルビの20字が任意の `ss03` でだけ選ばれ、字送りと縦組原点を保ち、行の上下からはみ出さないこと。`palt`・`vpal` との併用でも、元の仮名と同じ送り・配置調整になること。
- 詰め機能は、`palt`+`chws`・`halt`（縦は`vpal`+`vchw`・`vhal`）の二重詰めを明示的に再現し、排他的な指定がBIZ UDPと同じ結果になること。
- 追加数字に役割ごとの共通CVTゾーンを使う縦方向のヒントを付け、上付き・下付き・分子・分母の数字が8〜24ppemのFreeType３モードで消えず、高さを保つこと。分母はゼロ基準線に揃え、分子・下付き・追加上付き６字もそれぞれ上下端が一致することを、輪郭とラスタで検査する。斜線に接する専用字形も含める。元の上付き¹²³⁴は独立した対照群として元フォントと画素比較し、ヒントを保つ。追加記号はヒントなしのままとする。複数輪郭の数字は、FreeTypeのヒント適用後の全点が同じ縦方向の変形に追従するかも検査し、カウンターだけが動かない不具合を検出する。

## 字の向きと位置の検査（横組・縦組）

`check.py` は `scripts/glyph_reference.py` で、字の向きや置き換え先の取り違えを４書体すべて、言語指定ja/en、横組・縦組で検査します。基準は Noto Serif/Sans CJK JP の低解像度の形と位置を記録した `tests/fixtures/glyph-reference.json` で、CIに Noto は不要です。

- 全字（漢字・ハングルを除く）で、そのままより反転・180度回転した形が基準に近ければ失敗する。
- BIZ UD・BIZ UDP と同じ字はデザインの差として位置の比較から除き、読書 UD で作った・変えた字の位置を基準と比べる。
- `vrt2` の欧字が、横組の字を右へ90度回した形であること。
- 上付き・下付き・分数・`tnum`・`hwid`・`fwid` の数字が、横組・縦組（`vert`・`vrt2`）とも同じ数字の形であること。

CI でわかったことは次のとおりです。

- どちらのエンジンでも、横組の `ALWAYS_UDP` の17字は BIZ UDP の字幅になり（`“ ”` は0.5 em、`—` は1 em）、`locl` が既定で効いています。
